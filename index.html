Research Directions

六个方向，撑起一个能长期跑下去的 Agent

常驻式 Agent 的难点不在"能不能调用模型"，而在"没人盯着的时候它还靠不靠谱"。下面六块是胖福科技持续投入的核心研究方向。

Super-agent 调度架构

以中枢 Agent 统领多个专职子 Agent：统一意图解析、计划拆解与优先级仲裁，把"一次性问答"升级为可编排、可中断、可续跑的多角色协作。

PLANNER / ROUTER / ARBITER

工单化任务分发

把每一次意图落成一张带状态机的工单：待派发 / 执行中 / 待确认 / 已完成 / 已补偿。重试、幂等、去重与人工介入点全部挂载在工单上，任务不会凭空消失。

TICKET STATE MACHINE

事件触发机制

定时脉冲、Webhook 回调、外部系统信号、会话消息统一收敛为事件总线。Agent 不再等用户开口，而是在事件到达时主动醒来推进任务。

CRON / WEBHOOK / SIGNAL

长上下文链式召回

摘要压缩 + 分层索引 + 按需回溯的组合策略：近期细节走原文，远期事实走索引，跨天任务靠链式召回把关键上下文逐段拉回，避免上下文无限膨胀。

SUMMARIZE / INDEX / RECALL

存算分离

会话态、长期记忆、向量索引与执行器解耦存放。执行节点可随时重建而不丢状态，存储与算力各自独立扩缩，长时间运行的成本可控。

STATE / VECTOR / SCALE

沙箱隔离方案

工具调用、代码执行与文件读写全部在受限沙箱内完成：资源配额、网络白名单、权限分级、高风险动作默认转人工审批，让"自主"不等于"失控"。

QUOTA / ALLOWLIST / APPROVAL
System Design

一次事件，如何在系统里走完全程

常驻式 Agent 的稳定性来自可追踪的链路：每一跳都有明确产物，每一次失败都有落点。以下是运行时主干与配套治理机制。

运行时主干链路

从信号到达，到结果沉淀与再次唤醒

事件接入定时 / Webhook / 消息
中枢裁决是否需要唤醒、优先级
上下文装配近期原文 + 索引召回
计划编排拆工单 / 选子 Agent
工单派发状态机落库、幂等键
沙箱执行工具链 + 模型调用
结果回填产物、轨迹、审计
沉淀与续步写记忆 / 唤醒下一工单
RESUME

断点续跑

执行进度随工单持久化，进程重启、模型超时、网络中断后均可从最近检查点继续，跨天任务不丢现场。

IDEMPOTENT

幂等与去重

同一事件重复投递只产生一张工单；外部写操作携带幂等键，避免重试造成副作用叠加。

BUDGET

成本与步数护栏

单工单步数上限、Token 预算、工具调用频率三层限流，超出即挂起转人工，防止失控式燃烧。

TRACE

全链路可回放

每一次决策、工具调用与模型输出都落为事件，可逐条回放复盘，问题定位不靠猜。

APPROVAL

高风险人工闸门

涉及资金、外发消息、删除类操作默认进入审批队列，Agent 负责准备，人来负责确认。

Delivery Pipeline

一个人，跑完从架构到上线的全流程

独立开发者不是"只能做 demo"。架构设计、模型集成、工具链开发到部署运维，全部由同一人闭环交付，沟通链路最短，方案与实现不会脱节。

架构设计

先定义清楚 Agent 要长期做什么、边界在哪，再决定调度形态与存储方案。

  • 场景与目标拆解
  • 调度与状态机设计
  • 成本与风险预估

模型集成

多模型分层接入，按任务难度路由，兼顾效果、延迟与预算。

  • 主 / 备模型路由
  • 结构化输出约束
  • 失败降级与重试

工具链开发

把真实业务动作封装成可控工具，配好权限分级与审计埋点。

  • 工具契约与鉴权
  • 沙箱与配额隔离
  • 高风险动作审批

部署上线

容器化交付、健康检查与可观测性齐全，交付即可长期运行。

  • 容器化与一键部署
  • 日志、指标与告警
  • 运维手册与移交
